# Оценка Data Encryption at Rest and In Transit

## 1. Классификация данных

| Класс данных | Категория | Чувствительность | Где хранится (at rest) | Где передаётся (in transit) | Профиль риска | Примеры |
|---|---|---|---|---|---|---|
| Персональные данные пациентов | PII | CRITICAL | PostgreSQL, S3/MinIO | Клиент - Gateway - Patient Service | Утечка: штрафы ФЗ-152, потеря репутации, судебные иски | ФИО, дата рождения, телефон, адрес, паспорт, СНИЛС |
| Медицинские данные | PHI | CRITICAL | PostgreSQL, S3/MinIO (сканы, карты) | Gateway - Patient Service, Lab Integration - Лаборатория | Утечка: нарушение врачебной тайны, репутационные потери | Диагнозы, результаты анализов, назначения, мед.карты |
| Финансовые данные | FIN | HIGH | PostgreSQL, 1С:Бухгалтерия | Gateway - Payment Gateway - Платёжная система, 1С - ФНС | Утечка: финансовые потери, нарушение PCI DSS | Платежи, чеки, зарплаты, налоговая отчётность |
| Кадровые данные сотрудников | HR | HIGH | 1С:Бухгалтерия, PostgreSQL | Gateway - 1С:Бухгалтерия | Утечка: нарушение ФЗ-152 (ПДн сотрудников), трудовые споры | Паспорта, ИНН, СНИЛС, трудовые договоры, зарплаты |
| Учётные данные и секреты | CRED | CRITICAL | Keycloak (PostgreSQL), Redis, Vault | Клиент - Gateway - Keycloak | Компрометация: полный доступ к системе, эскалация привилегий | Пароли (хэши), токены OAuth2, OTP, ключи шифрования, сертификаты |
| Согласия на обработку ПДн | PII | HIGH | PostgreSQL | Gateway - Consent Management | Утрата: невозможность подтвердить правомерность обработки при проверке | Дата согласия, объём, цель обработки, отзыв |
| Данные ТМЦ и закупок | INT | MEDIUM | 1С:Торговля и склад | Gateway - 1С:Склад | Утечка: коммерческие потери, информация о поставщиках | Номенклатура, цены закупки, остатки, поставщики |
| Журналы аудита | INT | MEDIUM | ELK Stack (Elasticsearch) | Сервисы - ELK (Filebeat/Syslog) | Утрата/подмена: невозможность расследования инцидентов | Логи доступа, действия пользователей, алерты |
| Обезличенные аналитические данные | ANON | LOW | ClickHouse | NiFi - Anonymization - ClickHouse | Минимальный: данные уже обезличены, реидентификация маловероятна | Агрегированная статистика, обезличенные ID |

## 2. Данные, необходимость защиты и инструменты

| Данные | В чём необходимость защиты | Инструменты защиты |
|---|---|---|
| **Персональные данные пациентов** (ФИО, телефон, паспорт, СНИЛС, адрес) | ФЗ-152 обязывает обеспечить конфиденциальность ПДн. Утечка ведёт к штрафам, судебным искам пациентов и потере доверия клиентов. | **At rest:** pgcrypto (AES-256 полевое шифрование), TDE PostgreSQL, SSE MinIO. **In transit:** TLS 1.3 (клиент-сервер), mTLS (сервис-сервис). **Контроль:** Vault (ключи), Ranger (RBAC/ABAC по тегу PII), DLP (блокировка экспорта), Atlas (Data Lineage). |
| **Медицинские данные** (диагнозы, анализы, мед.карты, сканы) | Врачебная тайна охраняется законом. Утечка диагнозов наносит непоправимый вред пациенту. Данные хранятся также в виде файлов (сканы, PDF). | **At rest:** pgcrypto (AES-256) для структурированных данных, SSE-S3 (AES-256-GCM) для файлов в отдельном бакете. **In transit:** TLS 1.3, mTLS между сервисами и лабораторией. **Контроль:** Ranger (доступ только для врача и пациента), Atlas (тег PHI), DLP (запрет копирования на USB/email), NiFi (обезличивание перед аналитикой). |
| **Финансовые данные** (платежи, чеки, зарплаты, налоговая отчётность) | PCI DSS для платёжных данных. ФЗ-152 для зарплатных данных сотрудников. Утечка финансовой информации создаёт риск мошенничества. | **At rest:** TDE PostgreSQL (AES-256), BitLocker/LUKS для 1С. **In transit:** TLS 1.3 (алгоритмы по требованиям PCI DSS) для платёжной системы, КриптоПро (ГОСТ) для ФНС. **Контроль:** Ranger (тег FIN, доступ: бухгалтер + кассир), аудит-лог всех финансовых операций в ELK. |
| **Кадровые данные сотрудников** (паспорта, ИНН, СНИЛС, трудовые, зарплаты) | ФЗ-152 распространяется на ПДн сотрудников наравне с клиентами. Утечка зарплат и паспортных данных ведёт к трудовым спорам и мошенничеству. | **At rest:** Шифрование на уровне 1С (BitLocker), при миграции на PostgreSQL: pgcrypto (AES-256). **In transit:** TLS 1.3 (Gateway - 1С). **Контроль:** Ranger (тег HR, доступ: только бухгалтерия), аудит доступа в ELK. |
| **Учётные данные и секреты** (пароли, токены, ключи, сертификаты) | Компрометация учётных данных даёт полный доступ ко всей системе. Это наиболее критичный класс данных с точки зрения каскадного ущерба. | **At rest:** Vault (шифрованное хранилище, Shamir seal), Keycloak (bcrypt для паролей), Redis (TTL, no persistence). **In transit:** mTLS для всех внутренних каналов, OAuth2/OIDC для токенов. **Контроль:** Vault (автоматическая ротация каждые 90 дней), cert-manager (автообновление TLS-сертификатов), Grafana (алерт на неудачные попытки входа). |
| **Согласия на обработку ПДн** (дата, объём, цель, статус) | ФЗ-152 требует подтверждения согласия на обработку. Без сохранных согласий компания не может доказать правомерность обработки данных при проверке Роскомнадзора. | **At rest:** TDE PostgreSQL (AES-256). **In transit:** TLS 1.3 (Gateway - Consent Service). **Контроль:** Ranger (запрет модификации/удаления, append-only), аудит-лог в ELK, Atlas (тег CONSENT). |
| **Данные ТМЦ и закупок** (номенклатура, цены, поставщики, остатки) | Коммерческая тайна. Утечка цен закупки и данных поставщиков даёт конкурентное преимущество конкурентам. | **At rest:** BitLocker/LUKS для 1С:Склад. **In transit:** TLS 1.3 (Gateway - 1С:Склад). **Контроль:** Ranger (тег INT, доступ: кладовщик + бухгалтерия), базовый аудит. |
| **Журналы аудита** (логи доступа, действия, алерты) | Целостность логов критична для расследования инцидентов ИБ. Подмена логов позволяет скрыть факт утечки. | **At rest:** Write-once хранение в Elasticsearch (ILM политики), шифрование индексов. **In transit:** TLS (Filebeat - Elasticsearch). **Контроль:** Запрет удаления/модификации (append-only), хэширование записей для контроля целостности, алерты на изменение конфигурации логирования. |
| **Обезличенные аналитические данные** (агрегаты, обезличенные ID) | Минимальный риск, но необходимо предотвратить реидентификацию через связывание наборов данных. | **At rest:** LUKS на уровне ФС для ClickHouse. **In transit:** TLS (NiFi - ClickHouse, ClickHouse - Superset). **Контроль:** Ranger (доступ: аналитик, запрет джойнов с оперативной БД), k-anonymity при обезличивании. |

## 3 Средства автоматизированного контроля

### 3.1. Управление ключами и сертификатами

| Средство | Что контролирует | Как работает |
|---|---|---|
| HashiCorp Vault | Ключи шифрования, секреты, сертификаты | Автоматическая ротация ключей по расписанию. Transit engine для шифрования/дешифрования без выдачи ключей сервисам. PKI engine для выпуска mTLS-сертификатов. |
| cert-manager (K8s) | TLS-сертификаты сервисов | Автоматический выпуск и обновление сертификатов через Let's Encrypt или внутренний CA (Vault PKI). Алерт за 30 дней до истечения. |

### 3.2. Классификация и маршрутизация данных

| Средство | Что контролирует | Как работает |
|---|---|---|
| Apache Atlas | Классификация данных, метаданные | Автоматическое присвоение тегов (PII, PHI, FIN, HR) при регистрации таблиц и полей. Data Lineage для отслеживания потоков данных. |
| Apache NiFi | Потоки данных, тегирование | Автоматическая проверка тегов при передаче данных. Данные с тегами CRITICAL/HIGH проходят обезличивание перед попаданием в аналитику. Блокировка нетегированных потоков. |
| Apache Ranger | Политики доступа | Автоматическое применение RBAC/ABAC политик на основе тегов Atlas. Запрет доступа к данным без соответствующей роли. |

### 3.3. Предотвращение утечек

| Средство | Что контролирует | Как работает |
|---|---|---|
| DLP Engine | Исходящие потоки данных | Сканирование исходящего трафика (email, HTTP, USB) на наличие PII/PHI паттернов. Блокировка или алерт при обнаружении. |
| API Gateway (Kong) | Входящий/исходящий API-трафик | Rate limiting, блокировка массового скачивания данных, валидация JWT. |

### 3.4. Мониторинг и алертинг

| Средство | Что контролирует | Как работает |
|---|---|---|
| ELK Stack | Аудит-логи, события безопасности | Централизованный сбор логов. Правила корреляции для обнаружения аномалий (массовый доступ к PII, вход из необычной локации). |
| Victoria Metrics + Grafana | Метрики инфраструктуры и безопасности | Мониторинг: истечение сертификатов, количество отказов авторизации, объём передаваемых данных. Алерты в Telegram/email. |
| Vulnerability Scanner (Trivy, ssl-test) | Конфигурация TLS | Автоматическая проверка: версия TLS, допустимые алгоритмы шифрования, срок действия сертификатов. Интеграция в CI/CD. |

## 4. Реестр программных и аппаратных средств защиты данных

### 4.1. Программные средства

| Средство | Тип | Назначение | Что защищает | Лицензия |
|---|---|---|---|---|
| HashiCorp Vault | Управление секретами | Хранение ключей шифрования, сертификатов, секретов. Автоматическая ротация. Transit engine для шифрования. | Все классы данных (ключи at rest), mTLS-сертификаты (in transit) | BSL (бесплатно для ограниченного использования) |
| PostgreSQL + pgcrypto | СУБД + расширение шифрования | Полевое шифрование AES-256 для PII/PHI полей. TDE для шифрования всего тома. | PII, PHI, FIN, HR, CRED, CONSENT (at rest) | PostgreSQL License (open source) |
| MinIO (SSE) | Объектное хранилище | Server-side encryption AES-256-GCM для файлов. Интеграция с Vault KMS. | PHI: мед.карты, сканы, документы (at rest) | AGPLv3 (open source) |
| Keycloak | IAM / Identity Provider | Аутентификация (OAuth2, OIDC), MFA, управление сессиями, bcrypt для паролей. | CRED (at rest), токены (in transit) | Apache 2.0 (open source) |
| Apache Ranger | Контроль доступа | RBAC/ABAC политики на основе тегов. Аудит всех решений по доступу. | Все классы данных (контроль доступа) | Apache 2.0 (open source) |
| Apache Atlas | Каталог данных | Классификация, тегирование, Data Lineage. Автоматическое обнаружение PII/PHI. | Все классы данных (классификация, линейдж) | Apache 2.0 (open source) |
| Apache NiFi | Управление потоками данных | ETL с проверкой тегов, маршрутизация с privacy-правилами, обезличивание. | PII, PHI (маршрутизация in transit, обезличивание) | Apache 2.0 (open source) |
| Kong API Gateway | API-шлюз | TLS termination, rate limiting, JWT-валидация, mTLS plugin. | Все данные (in transit, периметр) | Apache 2.0 (open source, Enterprise - платная) |
| ELK Stack | Логирование и аудит | Сбор, хранение и анализ аудит-логов. Обнаружение аномалий. | Журналы аудита (at rest + in transit) | Elastic License / SSPL (open source core) |
| Victoria Metrics | Метрики | Хранение метрик безопасности, мониторинг SLA по шифрованию. | Метрики инфраструктуры | Apache 2.0 (open source) |
| Grafana | Визуализация и алерты | Дашборды безопасности, алерты на аномалии и истечение сертификатов. | Контроль всех средств защиты | AGPLv3 (open source) |
| DLP Engine (OpenDLP / MyDLP) | Предотвращение утечек | Контроль исходящих каналов: email, HTTP, USB. Блокировка передачи PII/PHI. | PII, PHI (контроль экспорта) | Open source / коммерческая |
| cert-manager | Управление сертификатами | Автоматический выпуск и обновление TLS-сертификатов в Kubernetes. | Все данные (in transit, сертификаты) | Apache 2.0 (open source) |
| Trivy | Сканер уязвимостей | Проверка конфигурации TLS, образов контейнеров, зависимостей. | Инфраструктура (контроль конфигурации) | Apache 2.0 (open source) |
| КриптоПро CSP | Криптопровайдер ГОСТ | Шифрование и ЭП для обмена с ФНС по ГОСТ. | FIN: налоговая отчётность (in transit) | Коммерческая лицензия |

### 4.2. Аппаратные средства

| Средство | Тип | Назначение | Обоснование |
|---|---|---|---|
| HSM (Hardware Security Module) | Аппаратный модуль | Хранение master-ключей Vault в аппаратном модуле (FIPS 140-2 Level 3) | Для CRITICAL данных (PII, PHI, CRED) рекомендуется хранить master-ключи в HSM. Защита от извлечения ключей даже при компрометации сервера. |
| SSD с аппаратным шифрованием (SED) | Накопители | Self-encrypting drives для серверов с базами данных | Дополнительный уровень защиты at rest на уровне носителя. При физическом хищении диска данные нечитаемы. |
| Сетевой firewall (NGFW) | Сетевое оборудование | Сегментация сети, контроль трафика между зонами | Разделение сети на зоны: DMZ (Gateway), внутренняя (сервисы), хранилища, аналитика. Контроль трафика между зонами. |
